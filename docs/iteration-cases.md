# 关键迭代：从发现问题到明确规则

以下来自项目决策和验收记录，不是本次重新执行的生产测试；不据此推导用户增长或商业收益。

## 案例一：无结束日不等于永远进行中

**问题**：只知道开始日期的优惠，不能一直作为当前活动展示，也不能臆造商家公布的结束日期。

**决策**：明确开始日但无结束日时，顺延一个自然月，在该日香港时间零点转入过期区；没有对应日取月末。已有明确结束日优先，没有合法开始日不推算。

**实现边界**：计算展示截止时间，不写回原文、证据和商家日期字段；列表、详情和过期页共用同一入口。

**验证记录**：2026-09-21 记录中，8 月 8 日开始的莎莎活动按 9 月 8 日归档，详情仍为「8月8日起」，API 的结束日期仍为空；发布前后优惠数量不变。相关前端提交为 `e3a1e50`，该 SHA 属于原开发历史。

可阅读[抽取的真实函数](../examples/offer-display-expiry.ts)及[独立规则测试](../examples/offer-display-expiry.test.mjs)。

## 案例二：有待审状态还不等于有审核闭环

**问题**：后台存在待审记录，不代表管理员会得知它，更不代表处理结果能进入用户页面。

**决策**：把待审事件、邮件通知、人工操作、发布同步与撤回视为完整流程；模型意见、人工修改和发布快照分开保存。

**真实验收**：2026-09-21 使用明确标注「链路验收，非真实优惠」的独立记录，依次完成待审产生、邮件送达、管理员确认收件、后台批准和正式页面展示。随后撤回，保留审计记录，未修改真实优惠。

**验证原则**：SMTP 接受邮件不等于用户收到；同步脚本返回不等于页面可读。分别确认实际收件、批次 ACK、页面与图片响应。这次验收没有调用 Kimi，不能冒充整条模型生成链路的验收。

## 案例三：把功能做出来不等于把交互做完整

**问题**：收藏在「我的」与列表之间不一致，自己的评论点赞在不同入口不同步，容易让用户怀疑操作没有生效。

**决策**：当前先采用统一的本地用户状态，页面读取同一数据来源；支持点赞与取消赞，不把界面上出现的默认内容当作真实收藏。

**验收重点**：从列表进入详情、操作后返回、进入「我的」、刷新页面，检查状态是否一致。仍未实现跨设备账号同步，清理浏览器数据或切换网站域名后状态不保证延续。

## 案例四：管理入口连不上，不一定是服务器故障

**问题**：电脑上的 SSH 隧道未运行时，私密后台打不开；旧启动脚本依赖中文标题判断，Windows PowerShell 编码差异会造成连接成功却报失败。

**改进**：使用稳定页面标识与只读审核 API 联合校验，避免代理干扰；区分端口被占用、SSH 退出与后台暂时不可用；不关闭未知进程。

**验证记录**：2026-09-30 在 Windows PowerShell 5.1 和 PowerShell 7 下成功启动并重复运行，复用同一 SSH 进程，页面和 API 均返回 200。未把后台改为公网访问，也没有修改生产数据。
